PROJECT-SCOPING COMMITMENTS

Set the rules.
Show the evidence.

Written scope before work

Define the task set, criteria, price, timeline, allowed tools, and acceptance process before beginning an engagement.

Verification requirements made explicit

Agree which credentials matter, the verification method, and who reviews the evidence before assigning work that requires those credentials.

Data boundaries by agreement

Document permitted environments, access, subprocessors, and any proposed third-party LLM use. Approval belongs in the agreed data-handling plan.

Traceable review and rights

Specify reviewer attribution, disagreement reporting, task ownership or licensing, retention, and deletion confirmation in the project agreement.

These are commitments about agreeing and documenting the work. They are not claims that a particular verification program, two-reviewer process, or customer environment is already operating.

Implemented on this site

  • Forms submit to a same-origin endpoint over the site’s HTTPS connection.
  • Requests are stored in a hosted object-storage bucket. There is no public endpoint for reading submissions.
  • Only the fields listed in the form are requested; no identity documents, licences, or production datasets are needed.
  • Requests do not pass through an external LLM service.

These statements describe the website forms, not a customer data-processing environment.

Controls to specify for your project

  • Which qualifications need verification, by whom, and how evidence is handled.
  • Whether identity checks or background checks are appropriate and agreed.
  • Allowed AI assistance, tool use, and the limits of any detection process.
  • Customer data isolation, access rules, approved subprocessors, and retention.
  • Ownership, licensing, confidentiality, and deletion arrangements.

No SOC 2, ISO certification, licence-verification program, background-check process, or automated AI-detection capability is claimed on this site.
