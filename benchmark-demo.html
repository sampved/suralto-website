01 / WHAT IS MEASURED?

Task success.

For this demo, a task either passes or fails. The score is the number of passes divided by the number of tasks, expressed as a percentage.

02 / WHY USE IT?

Find strengths and gaps.

Category views reveal differences an overall score can hide. A real benchmark can guide model selection and help prioritize improvement.

03 / HOW TO READ IT?

Keep the context.

Real comparisons need consistent tasks, rubrics, tool access, model versions, and test conditions. Higher scores only describe performance on that test.

Demo methodology and limitations

All four system names and every result are invented. Each category contains 100 fictional tasks per system. “All tasks” combines the five categories for 500 tasks, giving each category equal weight. No model was tested. There are no confidence intervals, external validation, or claims of statistical significance. A real evaluation should disclose task provenance, grading, repeat runs, uncertainty, test dates, and contamination controls.
